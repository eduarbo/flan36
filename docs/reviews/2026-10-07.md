# Flan36 engineering audit

Follow-up: [corrections and current delivery evidence](2026-10-07-corrections.md). This report preserves the original audit snapshot.
**7 October 2026 · Revision I · digital prototype**

The published viewer matches its current assets, but the documented FreeCAD editing workflow has defects. Fix parameter propagation and restore current validation before making further printable changes. PCB routing, integrated firmware and physical qualification remain unfinished.

Scope: CAD, electronics, component coverage, print exports, configuration behavior, public delivery, documentation and source provenance at commit `8cd6ec78527d732652e206bcf46da0365772c17b`. This audit changes no product geometry, electronics, artwork or viewer behavior. [Machine-readable evidence](../../validation/audit-20261007.json).

## Findings requiring correction

### A1 Display movement leaves its contacts behind

**Medium severity; correct before relying on manual stack edits.** The [FreeCAD example](../freecad.md#2-move-the-display) changes `DisplayShiftY` from 2.4 to 3.4 mm. The display board and window follow it, while the male contacts, spacer, socket and solder reserve keep their old Y coordinate. A nominal 1 mm misregistration results.

The missing dependencies are in [level_stack.py](../../tools/freecad/level_stack.py#L183). A native probe confirmed the board moves −1 mm while the male contacts remain fixed. The edited Talavera frame also intersects the glass by **2.785 mm³**, while still reporting a valid solid. Bind the complete mating chain and its service clearances to one datum; test the documented edit and a save/reopen cycle. Moving the mechanical model still must not silently move KiCad footprints.

### A2 The window control does not consistently control the finished frame

**Medium severity.** R4 color regions have fixed XY apertures. The final frame fuses them directly into the edited structural blank. Enlarging `WindowMargin` or moving the display can therefore leave color material in the newly opened region.

The native Talavera probe changed `WindowMargin` from **0.10 to 0.30 mm**, but the completed frame's minimum glass gap remained **0.10 mm**. Color material occupied **14.545 mm³** outside the updated blank. The cause is [approved_frames.py](../../tools/freecad/approved_frames.py#L110): only extrusion height is parametric. Test the completed frame against its current blank and glass, rather than checking the window cutter alone. Preserve the approved artwork at the reference dimensions; define explicitly how it responds to supported dimension edits.

### A3 Raising the frame changes inlay depth and reduces backing

**Medium severity.** The documented `FrameTop +0.4 mm` example leaves the ordinary inlay floor fixed at Z13.19. Its depth becomes **0.8 mm**, although `InlayDepth` still says 0.4 mm. With the 1.4 mm roof, the ordinary cavity ceiling rises to Z12.59: the calculated backing becomes **0.6 mm**, below the declared 0.8 mm minimum.

Native readback confirmed the fixed inlay floor and rising cavity ceiling. Use a roof-relative inlay floor or reject unsupported edits. Verify actual sections through ordinary artwork and the distinct collar/pin-cover regions. The nominal 13.59 mm reference is separate from this edited-state defect.

### A4 Every case base intersects the nominal USB corridor

**Medium severity; reproduced at the unchanged reference dimensions.** The exporter tests its **12 × 5 mm plug envelope** against the frames, but omits the case bases. All four case styles, on both halves, overlap that same insertion corridor by **3.120 mm³**. The overlap occupies Z6.10–6.30: **0.20 mm** of the base's upper wall. The plates do not intersect it.

This contradicts clearance of that modeled plug envelope; it does not prove every real USB cable is blocked. Check the purchased plug, add the required local access clearance, and include every base/plate/frame in the corridor regression. No case was altered by this audit.

### A5 Component coverage omits the installed diodes

**Medium severity; coverage gap, not a demonstrated collision.** Both PCBs contain 18 SOD-123 diodes on `B.Cu`, but none has an installed 3D model. The native assembly and nominal collision set omit all **36 diodes**. A pinned SOD-123 source already exists in [components/sources.json](../../components/sources.json).

Register their actual footprint positions and underside height, then check the base, PCB, hot-swap sockets and assembly access. The hot-swap socket's own assembly datum and floor clearance remain a previously documented qualification gap.

### A6 Several advertised checks no longer test the current product

**Medium severity.** Three failures were reproduced:

| Check | Failure on this snapshot | Meaning |
|---|---|---|
| `viewer/hex-check.cjs` | Waits for retired `handheld` | Stops before completing current frame/key HEX coverage |
| `viewer/level-check.cjs` | Expects Z13.39 instead of Z13.59 | Old geometry expectation |
| `tools/freecad/check_revI.py` | Line 45 expects legacy no-case import to restore Level | The contract correctly defaults that legacy input to Solid; the test fails before save/reopen |

The native test also retains an obsolete Z2 battery assertion, versus current Z1.4. Its old receipt cannot certify the current source. A temporary HEX test using the installed Game Boy selector passed desktop, actual clipboard copy/paste, invalid-input rejection, persistence and 390 px mobile editing. That proves the current control works; it does not repair the committed test.

Create a documented current audit entry point and separate historical regression receipts from executable current acceptance. Keep negative tests for changed datums, retired options and unsupported edits.

### A7 Current documentation and presentation disagree

**Medium severity for dimensions; low severity for presentation.** The current [customization table](../customize.md#print-a-themed-display-frame) says roof **1.2 mm** and glass margin **0.4 mm**. The current source uses **1.4 mm** and **0.1 mm**. The companion macro still labels its dialogs and exported filename `Filo36`. The README hero shows the retired Flan artwork, while the viewer starts with Talavera.

The native historical collection is deliberately retained, as [the selection record explains](../../design/approved-viewer-selection.md); its existence is not a newly discovered regression. Make the active entry points and illustrations agree, while preserving historical sources explicitly. Viewer-exported configurations already materialize their colors for native import.

## Checks that passed

- Original Piantor key centers and angles, with 36 keys and no sixth finger column.
- All **22 retained native frame bodies** at reference dimensions; approved material regions and the nominal **0.10 mm** glass gap.
- Expanded cap/screw sweep: **6,048** enabled cap/key/rotation/head pairs, including poses rejected by neighboring caps; no conservative contact, minimum nominal gap **4.091 mm**.
- F/J positions `K14` use Normal Homing by default on both halves. Center relief relative to the ordinary cap is **0.300 mm**; the Saddle Homing source has the same measured relief.
- Viewer camera continuity, component visibility, isolation and hover behavior, frame collection/orientation, colors, row direction, battery leads and display seam.
- Public online/offline HTML matched local bytes. The five active frames, selected configuration and downloaded STL print assets matched the tested sources, with no browser runtime errors.
- **256 viewer input hashes**, **49 pinned source/license assets** and all audited local documentation file targets matched. This is provenance checking, not a new legal opinion.

## Electrical and manufacturing status

Fresh KiCad 10.0.6 ERC returned **0 violations** per schematic. PCB DRC returned **0 geometric violations**, **104 unconnected items per half**, and **189 schematic-parity warnings per half**. Those warnings comprise 146 net-name/unconnected-pad differences, 38 value differences and five board-only mounting footprints. An independent normalized comparison found **108 schematic pin/net associations per half with no connectivity or symbol-path mismatch**. Do not misreport the warnings as 189 wrong electrical connections. Reconcile them before routing so later discrepancies remain useful signals.

No integrated firmware build is present. Exact supplied connectors, hot-swap seating, battery tolerances, retention force, printed threads, charging, RF, sleep/wake and measured consumption remain open. Both battery profiles are nominal envelopes; neither has physical fit acceptance. Selected-parts STL/3MF downloads are prototype geometry, without a qualified slicer profile or finished toolpath. Hanafuda remains approved and pending integration.

## Performance and link checks

Three isolated desktop samples on the same local server gave a median ready time of **568 ms** and about **95 MiB JavaScript heap** for the current online viewer. The historical comparison measured 3,661 ms and about 426 MiB. This establishes a local improvement, not physical-phone or network performance.

The online HTML remains **49,743,957 bytes**, about **47.4 MiB before HTTP compression**. Test a real mobile device and constrained network before declaring mobile loading solved; consider further geometry delivery improvements only with export-fidelity checks.

Of 50 public BOM URLs, 48 answered the HEAD check. Arrow's socket PDF timed out and C&K's switch PDF returned 403. These two results are inconclusive access checks, not proof that the datasheets are gone. No live stock, price or interchangeable-parts approval is inferred.

## Correction order

1. Repair the parameter dependency chain and USB access; enforce frame/window/backing invariants on edited geometry.
2. Restore the current native save/reopen and viewer tests; align the dimension table and active presentation.
3. Add diode and qualified hot-swap envelopes, then complete component and service-access checks.
4. Reconcile schematic parity, route the PCBs and implement the firmware against the settled pin map.
5. Print interface coupons and verify the purchased parts, then a full half, then the complete wireless keyboard. Integrate Hanafuda without losing its approved geometry.

Two independent read-only reviews agreed on this priority after one focused severity discussion. The initial HIGH assessment of the display edit was reduced to MEDIUM because the error is in a reversible prototype-edit workflow and no physical harm or production use is established. [Original assessments and disposition](../../design/reviews/audit-20261007/). All 463 frozen review inputs remained unchanged.

## Reproduce

Use the repository's pinned viewer dependencies, a Playwright Chromium runtime, FreeCAD and KiCad 10.0.6. Set `FLAN36_PLAYWRIGHT_MODULE` and `FLAN36_BROWSER` when using an existing test runtime. Python mesh checks need NumPy and Shapely. No command below saves over the native source.

```sh
python3 tools/audit_current.py
python3 tools/audit_assets.py
python tools/audit_keycap_sweeps.py
# Use KiCad's Python for pcbnew:
python tools/audit_electrical.py
python3 tools/freecad/run_macos.py tools/freecad/check_approved_frames.py \
  --source mechanical/revI/Flan36.FCStd \
  --report build/audit-20261007/native-frames.json
python3 tools/freecad/run_macos.py tools/freecad/audit_parameters.py
node viewer/loading-check.cjs
node viewer/public-check.cjs 8cd6ec78527d732652e206bcf46da0365772c17b
```

`audit_current.py` records failures instead of treating an unrouted board as passing. Detailed outputs, disposable test profiles, downloads and screenshots under ignored `build/` are reproducible evidence. The committed receipt preserves the observations, hashes, current source snapshot and the limits of each check.

The parameter probe recomputes Talavera and its dependency graph in memory; it does not certify every arbitrary parameter combination or the other designs after edits. Reference-dimension frame checks cover all 22 retained native bodies. USB checks use the unchanged baseline case solids. Native files remain byte-identical.
